# Relic 0.3.0 (beta)

Auto-analysis is complete. Relic now finds functions without unwind info, rebuilds C++ classes
from RTTI, and resolves indirect and virtual calls on every processor it supports. It is also
about five times faster on large binaries. Overall progress against the goal (IDA Pro 9 +
Hex-Rays) is about 88%, up from 83%.

## New since 0.2.0

- **Functions without `.eh_frame`**:
  - Functions that never return are inferred from their code, so callers no longer run on into
    the next function.
  - Tail calls are recognized (`endbr64` targets, jumps after an epilogue).
  - Functions reached only through pointers in data are found.
  - Numbers are no longer mistaken for function pointers.
  - Result on bash with `.eh_frame` removed: 99.96% of its functions found (was 99.0%). The
    functions that ran into the next one went from 140 to 1.
- **Speed**: x86 decoding no longer builds capstone's operand detail it does not need. Function
  discovery on bash takes 7 seconds (was 34).
- **Indirect calls**:
  - Calls through function-pointer variables are resolved on x86, ARM, AArch64, MIPS, RISC-V
    and PowerPC.
  - The targets appear as cross references and in the listing (`; → print_and_abort`).
  - A call through a variable that only holds functions that never return is itself treated as
    never returning.
- **C++**:
  - Classes, bases and vtables are rebuilt from RTTI, for gcc/clang (Itanium) and MSVC, in
    stripped binaries too.
  - Virtual methods get names such as `Dog::vfunc2`, and the new `relic classes FILE` lists the
    classes.
  - Virtual calls are resolved by following objects through registers and stack slots, on
    x86-64, x86 and AArch64, at `-O0` and `-O2`. An object's possible classes come from:
    - constructors
    - vtables stored in place
    - `dynamic_cast` results, down to the right base subobject's thunk
    - the objects functions return or are passed
    - `this` in a virtual method
- **Data among code**:
  - On x86, a string, table or table of function pointers inside `.text` is shown as data, not
    code.
  - A table of function pointers there leads to its functions.

## Known limits

- No x87 floating point and no by-value struct arguments or returns in the decompiler.
- Virtual calls on objects are followed on x86 and AArch64 only.
- The debugger needs `gdb` (and `qemu-user` / wine for other systems' programs).
