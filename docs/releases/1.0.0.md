# Relic 1.0.0

The first stable release. Since 0.3.0:
- The type system knows libc's flag constants and Microsoft's bit-field layout.
- The decompiler prints SSE/AVX code as Intel intrinsics and has about half the gotos it started
  with.
- PowerPC64 ELFv1 decompiles.
- Seven more processors can be disassembled, including WebAssembly modules.

Overall progress against the goal (IDA Pro 9 + Hex-Rays) is about 91%, up from 88%.

## New since 0.3.0

- **Decompiler output**:
  - About half as many gotos: on the benchmark binaries, true, cat, gzip and grep went from 3300
    gotos to 1798. Changes behind this:
    - Loops whose exits meet get one follow.
    - A small return is copied instead of jumped to.
    - A goto to what comes next anyway is dropped.
    - `else if (c2) goto L` into the middle of the then branch becomes
      `if (c1 || c2) { if (c1) ...; ... }`.
  - Switches no longer get duplicated `break`s.
  - Unsigned ↔ floating-point conversion sequences print as `(double)(uint64_t)x` and
    `(uint64_t)d`.
  - SSE/AVX vector code prints as Intel intrinsics (`_mm_add_epi32`, `_mm256_...`).
  - Pointer arithmetic is scaled by the element size.
- **Type system**:
  - Constant arguments of libc calls print as their header names:
    - `mmap(0, n, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0)`
    - `open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644)`
    - `socket(AF_INET, SOCK_STREAM, 0)`
    - `setvbuf(stdout, 0, _IONBF, 0)`
  - In an imported header, two or more `#define`s that share a prefix become an enum. Integer
    parameters of that group's name take it: `set_mode(MODE_READ | MODE_EXEC)`.
  - PE/COFF structs use Microsoft's bit-field layout, which matches MinGW's sizes.
- **Processors**:
  - PowerPC64 ELFv1 (big-endian, function descriptors in `.opd`) decompiles.
  - New disassembly-only processors, with function discovery, control flow and listing:
    - SPARC / SPARC V9
    - SystemZ
    - M68K
    - SH
    - TriCore
    - eBPF
    - WebAssembly modules (new loader)
- **ARM**: literal pool words that follow a call which never returns are shown as data, not
  decoded as instructions.
- **Parameters**: an argument register that a function passes to a call untouched now counts as
  a parameter when a later register is used. An indirect call with known targets takes their
  parameters.

## Known limits

- No x87 floating point and no by-value struct arguments or returns in the decompiler.
- Large state-machine functions (gnulib `quotearg`, gzip's deflate) still print with many gotos.
- Virtual calls on objects are followed on x86 and AArch64 only.
- The debugger needs `gdb`. Programs for other systems also need `qemu-user` or wine.
