# Relic 1.0.0

This is the first stable release. Most of the work since 0.3.0 went into making the pseudocode
nicer to read. There are about half as many gotos as before, SSE/AVX code reads as Intel
intrinsics, and libc flag arguments show up as their names. PowerPC64 ELFv1 now decompiles too,
and seven more processors can be disassembled. I'd put the overall state at about 91% of IDA
Pro 9 + Hex-Rays, up from 88%.

## What's new

### Pseudocode

The goto count on my benchmark binaries (true, cat, gzip and grep) went from 3300 to 1798. The
fixes involved:

- Loops whose exits all lead to the same place now get a single follow block.
- A short return gets copied instead of jumped to.
- A goto to the very next statement is dropped.
- `else if (c2) goto L`, where L is in the middle of the then branch, is rewritten as
  `if (c1 || c2) { if (c1) ...; ... }`.

Other output fixes: switch cases no longer get a second `break`, and unsigned ↔ float
conversions print as plain casts like `(double)(uint64_t)x`. SSE/AVX vector code now shows as
Intel intrinsics (`_mm_add_epi32`, `_mm256_...`). Pointer arithmetic is scaled by the element
size.

### Types

Constant arguments to libc calls print with their header names:

```c
mmap(0, n, PROT_READ | PROT_WRITE, MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
socket(AF_INET, SOCK_STREAM, 0);
setvbuf(stdout, 0, _IONBF, 0);
```

If you import a header, any group of two or more `#define`s sharing a prefix becomes an enum.
Integer parameters named after that group then use it, e.g. `set_mode(MODE_READ | MODE_EXEC)`.
Structs in PE/COFF binaries now use Microsoft's bit-field layout, so the sizes match what MinGW
produces.

### Processors

PowerPC64 ELFv1 (big-endian, with function descriptors in `.opd`) now decompiles. These can now
be disassembled, with function discovery and control flow, but not decompiled: SPARC and SPARC
V9, SystemZ, M68K, SH, TriCore, eBPF, and WebAssembly modules (which needed a new loader).

### Smaller fixes

- On ARM, the literal pool after a call that never returns is shown as data rather than decoded
  as instructions.
- A register a function hands to a call untouched now counts as one of its parameters, as long
  as a later argument register is used.
- An indirect call whose targets are known takes their parameters.

## Known limits

- The decompiler doesn't handle x87 floating point or structs passed and returned by value.
- Big state-machine functions (gnulib's `quotearg`, gzip's deflate) still have a lot of gotos.
- Virtual calls through objects are only followed on x86 and AArch64.
- The debugger needs `gdb`, plus `qemu-user` or wine for programs from other systems.
- What's left to do is in [TODO.md](https://github.com/ljw097/relic/blob/main/TODO.md).
