# Relic 1.7.0

The decompiler's output now compiles again and *computes what the program computes* more often
than Ghidra's, angr's or RetDec's, measured by running it. Function detection is exact or close
to it on every benchmark build. Most of what changed was found by the new benchmarks.

## Benchmarks

[docs/benchmarks.md](../benchmarks.md) now scores decompiler output on more than "is it C":

- **Behavioural equivalence:** 42 functions (`tools/bench/equiv.c`) decompiled from stripped
  builds, compiled again and run against the original on 40 inputs each: Relic 81 of 84, Ghidra
  75, angr 67, RetDec 37.
- **Control-flow and data-flow similarity** to the source (graph-kernel similarity of gcc's CFG
  and SSA def-use graphs), and **types** against DWARF: Relic gets the kind and size of 81.5% of
  parameters and results right (angr 71.8%, Ghidra 40.9%) and the number of parameters for
  95.4% of functions.
- **Function detection:** F1 1.000 at -O0 and on AArch64, 0.996 at -O2, 0.995 without
  `.eh_frame` (Ghidra 0.73–0.98, angr 0.89–0.97).

`tools/decomp_quality.py` and `compare_decompilers.py --save` run it; `tests/test_equiv.py`
runs the equivalence test on every change.

## Fixed: pseudocode that computed the wrong thing

- Signed 64-bit `/` and `%` (`cqo; idiv`) printed as a 128-bit division of an unsigned
  dividend, wrong for negative values: now `a / b`.
- Large negative constants in signed comparisons printed unsigned (`0xffffffff80000000`),
  which made the comparison unsigned: now `-0x80000000LL`. Unsigned operands of signed
  operations are cast to signed.
- `int *` arithmetic added a byte offset as elements (an overrun); a struct pointer moved by its
  size printed `p += 8` (8 structs): now `p++`.
- A struct field overlapping an earlier one was used by name but not declared (the function
  didn't compile).
- Rotates and add/subtract overflow flags print as C, not `__rol()` / `__sborrow()`.

## New

- **Parameters:** one after an unused parameter is no longer lost (`lua_typename(L, t)` had
  none and read `rsi`); registers handed to a callee count; a parameter only passed on gets the
  type the callee gives it (`char *` when it reaches `strlen`).
- **Variadic functions** (x86-64): `int sum(int a1, ...)`, and calls to them pass the extra
  arguments (`sum(3, a1, 2, 3)`), where `luaL_error` used to take 14 parameters.
- **Computed `goto`** (GNU C `goto *table[op]`, Lua's interpreter loop): the labels belong to
  their function, which decompiles whole as a `switch`, on x86-64 and AArch64. They used to be
  84 separate functions.
- **Switch lookup tables** gcc makes (`CSWTCH`) are declared with their contents
  (`static const int tbl_30e0[7] = { 2, 1, 1, 1, 1, 3, 2 };`) instead of read by address.
- **libgcc's 128-bit helpers** (`__umodti3`, `__udivti3`, `__multi3` ...), when the symbol table
  or library signatures name them, are the operators they implement.

## Also fixed

- A switch's bounds check with moves between the `cmp` and the branch was missed, so the table
  was read to its 512-entry cap and one function swallowed the eleven after it (zstd).
- Big functions decompile faster: Lua's ~700-block interpreter loop in 18 s instead of 47 s,
  same output.

## Versioning

A MINOR release: new features and fixes, nothing removed or changed incompatibly.
