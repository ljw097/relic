# Relic 1.0.2

Another bug-fix release. The debugger was mangling program arguments that contained `$`, a few
32-bit programs decompiled wrongly, and broken or deliberately malformed files could crash or
hang the analysis.

## Download

| System | File |
|---|---|
| Windows (x86-64) | `relic-1.0.2-windows-x86_64.exe` |
| Linux (x86-64) | `relic-1.0.2-linux-x86_64.tar.gz`: one file, `relic` |
| macOS, Apple silicon | `relic-1.0.2-macos-arm64.zip`: `Relic.app` |
| macOS, Intel | `relic-1.0.2-macos-x86_64.zip`: `Relic.app` |

The macOS app isn't signed, so right-click it and choose Open the first time. The wheel is
attached too, for pip (Python 3.10+).

## Fixed

**Program arguments in the debugger now reach the program exactly as you typed them.** gdb
starts the program through a shell, and the shell was expanding the arguments: `%7$p` arrived as
`%7`, `$HOME` got replaced, and anything in backticks actually ran. That's a real problem when
you're testing format string exploits. Quotes and backslashes now pass through untouched, and
the program's path can contain `"`.

**Some `gcc -m32 -O0` programs decompiled `main` with a call that doesn't exist.** The stack
cleanup after a call (`add esp, 16`), followed by a jump to the function's shared exit, was being
read as a tail call. That turned the exit code into a separate function (`v1 = sub_1270();
return v1;`). It's part of `main` again.

**ELF files without usable section headers now open** instead of crashing. That covers
`sstrip`ped programs and files whose section headers are broken on purpose (pointing outside the
file, or with a bad name table), which is a common anti-analysis trick. The kernel doesn't need
section headers to run a program, and now Relic doesn't either: it loads from the program
headers and gets the imports, libraries and exported symbols from the dynamic segment. Info
tells you when the section headers were ignored.

**Truncated or malformed files** now give a short "malformed or truncated file" error instead of
a Python traceback.

**The analysis no longer hangs on a corrupted size field.** A single bad byte in an ELF
`.init_array` size or a PE section's virtual size could keep the analysis busy for minutes.
Scans now stop at the end of the data that's actually in the file.

**Project files** (`FILE.relic.json`):

- A failed save no longer leaves a half-written file behind; the old one is kept.
- If the project file can't be read, the binary still opens, without it. You get a warning (in
  the terminal, or a dialog in the GUI), and the unreadable file is kept as
  `FILE.relic.json.bak` the next time you save.

**Lumina**: `relic lumina serve` now rejects malformed requests with an error. Before, a negative
`Content-Length` left the request hanging forever. Pulling now skips broken entries in a store.
