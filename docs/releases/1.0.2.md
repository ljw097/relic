# Relic 1.0.2

A bug-fix release. The debugger expanded `$` in program arguments, some 32-bit programs
decompiled wrongly, and damaged or deliberately broken files could crash or hang the analysis.

## Download

| System | File |
|---|---|
| Windows (x86-64) | `relic-1.0.2-windows-x86_64.exe` |
| Linux (x86-64) | `relic-1.0.2-linux-x86_64.tar.gz`: one file, `relic` |
| macOS, Apple silicon | `relic-1.0.2-macos-arm64.zip`: `Relic.app` |
| macOS, Intel | `relic-1.0.2-macos-x86_64.zip`: `Relic.app` |

The macOS app is not signed: the first time, right-click it and choose Open. The wheel is also
attached, for installing with pip (Python 3.10+).

## Fixed

- **Debugger: program arguments now reach the program exactly as typed.**
  - gdb starts the program through a shell, and the shell used to expand arguments: `%7$p`
    arrived as `%7`, `$HOME` was replaced, and text in backticks ran as a command.
  - Quotes and backslashes are passed as typed too.
  - The program's path may now contain `"`.
- **32-bit x86 programs (`gcc -m32 -O0`): `main` decompiled with a call that does not exist.**
  - The cleanup after a call (`add esp, 16`) followed by a jump to the shared end of the
    function was read as a tail call.
  - That shared end became a function of its own (`v1 = sub_1270(); return v1;`). It is now
    part of `main` again.
- **ELF programs without usable section headers now open** instead of crashing. The kernel runs
  them, and Relic now loads them the same way, from the program headers. This covers:
  - `sstrip`-ed programs;
  - section headers that point outside the file or have a broken name table (an anti-analysis
    trick).

  Imported functions, libraries and exported symbols are recovered from the dynamic segment.
  `Info` says when the section headers were not used.
- **A truncated or malformed file** now gives a short "malformed or truncated file" error
  instead of a Python traceback.
- **The analysis no longer hangs on a corrupted size field.** One damaged byte in an ELF
  `.init_array` size or a PE section's virtual size could make the analysis run for minutes.
  Scans now stop at the end of the bytes the file actually holds.
- **Project files (`FILE.relic.json`):**
  - Saving no longer leaves a half-written file when the write fails: the old file stays.
  - A project file that cannot be read no longer stops the binary from opening. Relic warns
    (in the terminal, or with a dialog in the GUI) and opens the binary without it.
  - The unreadable file is kept as `FILE.relic.json.bak` the next time you save.
- **Lumina:**
  - `relic lumina serve` answers malformed requests with an error. Before, a negative
    `Content-Length` left the request waiting forever.
  - Pulling skips malformed entries from a store.
