# Relic 1.1.1

A bug-fix release. Automatic names no longer slow down opening large binaries, a few names they
suggested were wrong, and pseudocode with two structs pointing at each other could crash.

## Download

| System | File |
|---|---|
| Windows (x86-64) | `relic-1.1.1-windows-x86_64.exe` |
| Linux (x86-64) | `relic-1.1.1-linux-x86_64.tar.gz`: one file, `relic` |
| macOS, Apple silicon | `relic-1.1.1-macos-arm64.zip`: `Relic.app` |
| macOS, Intel | `relic-1.1.1-macos-x86_64.zip`: `Relic.app` |

The macOS app is not signed: the first time, right-click it and choose Open. The wheel is also
attached, for installing with pip (Python 3.10+).

## Fixed

- **Opening a large stripped binary is fast again.** To name a function from its `assert()`,
  1.1.0 decompiled the whole function, together with every function it calls. On `gdb` that added
  over half a minute to the analysis. The name is now read from the instructions just before the
  `assert()` call. Full decompilation is used only when that does not find it, for example on
  32-bit x86. The names given are the same.
- **Variables named after the function that set them could get a broken name.**
  `initialize_table()` gave `ialize_table`, and `calculate_sum()` gave `ulate_sum`. A prefix
  such as `get`, `init` or `calc` now counts only as a word of its own, as in `get_config` or
  `readHeader`.
- **A variable no longer gets the same name as an automatically named function**, for example
  `usage` or `xmalloc`.
- **The pseudocode no longer crashes when two recovered structs point at each other**, for
  example a list node pointing to its list and the list back to the node. Some functions of
  `bash` showed a "maximum recursion depth exceeded" error instead of their code.
- **The GUI now follows `RELIC_AUTO_NAMES=0`**, as the command line does, until View > Automatic
  names is used. Before, the GUI turned automatic names on regardless.
