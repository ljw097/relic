# Relic 1.1.1

A bug-fix release, mostly for the automatic names that came in 1.1.0. They were slowing down
large binaries and occasionally got a name wrong. There's also a crash fix for pseudocode with
two structs that point at each other.

## Download

| System | File |
|---|---|
| Windows (x86-64) | `relic-1.1.1-windows-x86_64.exe` |

The macOS app isn't signed, so right-click it and choose Open the first time. The wheel is
attached too, for pip (Python 3.10+).

## Fixed

**Large stripped binaries open quickly again.** To read the name a function passes to
`assert()`, 1.1.0 decompiled the whole function, and every function it called along with it. On
gdb that added more than half a minute to the analysis. Now the name is read straight from the
instructions just before the `assert()` call. Full decompilation is only the fallback, for
example on 32-bit x86, where arguments go on the stack. The names come out the same.

**Some variable names came out mangled.** A variable set from `initialize_table()` was named
`ialize_table`, and one from `calculate_sum()` became `ulate_sum`. A prefix like `get`, `init` or
`calc` is now only dropped when it's a separate word, as in `get_config` or `readHeader`.

**A variable could end up with the same name as an automatically named function**, such as
`usage` or `xmalloc`. That can't happen anymore.

**Two structs pointing at each other crashed the pseudocode**, for example a list node that
points to its list while the list points back to the node. A few functions in bash showed
"maximum recursion depth exceeded" instead of their code.

**The GUI ignored `RELIC_AUTO_NAMES=0`.** The command line respected it, but the GUI turned
automatic names on regardless. Now the GUI follows it too, until you change View > Automatic
names yourself.
