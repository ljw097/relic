# Relic 0.2.0 (beta)

The big change in this release is that you no longer need Python: Relic now ships as a single
executable for Windows, Linux and macOS. Just download it and run it. It starts with no file
open; use File > Open (`Ctrl+O`), File > Open Recent, or drag a file onto the window.

By my rough count it's now at about 83% of IDA Pro 9 + Hex-Rays, up from 76%.

## Download

| System | File |
|---|---|
| Windows (x86-64) | `relic-0.2.0-windows-x86_64.exe` |
| Linux (x86-64) | `relic-0.2.0-linux-x86_64.tar.gz`: one file, `relic` |
| macOS, Apple silicon | `relic-0.2.0-macos-arm64.zip`: `Relic.app` |
| macOS, Intel | `relic-0.2.0-macos-x86_64.zip`: `Relic.app` |

The macOS app isn't signed, so the first time you'll need to right-click it and choose Open.
The same executable also runs the command-line tools (`relic info FILE`, `Relic.exe decompile
FILE`, and so on). The wheel is still attached if you'd rather install with pip (Python 3.10+).

## What's new

Mach-O support is in: executables, dylibs, bundles, universal binaries, object files and the
chained fixups macOS 12 uses. Objective-C metadata is read too, so methods get their real names
even in stripped binaries, and message sends show up in the pseudocode the way you'd write
them, e.g. `[obj speak:"woof" times:n]`.

New processors: big-endian MIPS, MIPS64, 32- and 64-bit PowerPC, and RV32. Windows programs can
now be debugged on Linux under wine, using Windows' own `gdbserver.exe`.

Function discovery got a lot better. `.eh_frame` is now used as a list of functions, which finds
99.9% of them in stripped bash. Switch tables that gcc sets up away from the jump are now
understood, as are negative case ranges and tail calls through function pointers. On stripped
bash, the number of indirect jumps left unresolved went from 103 to 12.

Smaller things in the decompiler: Apple's arm64 calling convention, clang's division and stack
protector idioms, and doubles that RV32 passes in register pairs.

## Known limits

- The decompiler doesn't handle x87 floating point or structs passed and returned by value.
- The debugger needs `gdb` (plus `qemu-user` or wine for programs from other systems).
