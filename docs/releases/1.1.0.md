# Relic 1.1.0

Two things in this one. Stripped binaries now get readable names for both functions and
variables, and 32-bit x86 code that uses floating point finally decompiles to C.

## What's new

### Automatic function names

In a stripped binary, a `sub_XXXX` function now gets a name when its code gives one away. The
strongest hint is `assert()`: it passes the function's own name, so you get the name from the
source (`table_insert`). Log and error messages that start with the function's name
(`"shell_getc: ..."`) work too. Beyond that, a function that just jumps to `puts` becomes
`j_puts` and is called with `puts`'s arguments. A wrapper that allocates memory and dies if that
fails becomes `xmalloc`. A function that prints "Usage:" and exits is `usage`, and one that
prints a message and never returns is `fatal`.

`relic funcs` shows why each name was given (`[auto: assert() names it]`). On stripped bash this
finds `shell_getc`, `execute_coproc` and `vidomove_dispatch`, among others.

### Readable variable names

Instead of `v1`, `a1` and `var_c`, variables are now named after how they're used:

- loop counters become `i`, `j`, `k`
- results of known calls get the obvious name: `fd = open(...)`, `fp = fopen(...)`,
  `len = strlen(...)`, `buf = malloc(...)`, `home = getenv("HOME")`
- results of the program's own functions take their name from the function, so
  `count_lines(...)` gives `lines`
- types suggest names too: `FILE *fp`, `struct stat st`
- an argument is named after the parameter it's passed as, as in `read(fd, buf, count)`
- simple patterns like `count`, `total` and `result` are recognized

Names you set yourself always win, a suggestion never reuses a name that's already taken, and
nothing changes in your project files. If you'd rather see the generated names, turn off View >
Automatic names, or pass `--no-auto-names` on the command line.

### x87 floating point on 32-bit x86

Functions that use `float` and `double` on 32-bit x86 now decompile to C instead of
`__asm("fld ...")`:

```c
float scale(float a1, float a2)
{
    return a1 * a2 + 1.5f;
}
```

This handles parameters, return values and call arguments (including `printf("%f")`), as well
as comparisons, conversions, and the rounding-mode switch compilers emit around a C cast.
`long double` is still shown as `__asm`.

## Improvements

- At `-O0`, parameters are used directly, instead of through the stack slot the compiler copies
  them into. So no more `var_1c = argc`.
- A variable used to index a stack array now reads as `buf[i]`, not `i[buf]`.
- Stack writes that nothing reads are left out of the pseudocode.

## Fixes

- A function containing `pop ss` no longer fails to decompile.
- Neither does one with a `float` constant close to `FLT_MAX`.

## Build

- CI and the release workflow now use the Node.js 24 versions of their actions, and the Ubuntu
  runner image is pinned to 24.04.
