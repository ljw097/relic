# Relic 1.1.0

Stripped binaries get readable names, and 32-bit x86 programs that use floating point decompile
to C.

| System | File |

## New

- **Automatic function names.** In a stripped binary, a `sub_XXXX` function gets a name from what
  its code shows:
  - the function name its `assert()` passes: the name the source gave it (`table_insert`);
  - a log or error message that names its function (`"shell_getc: ..."`);
  - a jump thunk: `j_puts`, called with `puts`'s arguments;
  - a wrapper that allocates and dies on failure: `xmalloc`;
  - `usage` (prints "Usage:" and exits) and `fatal` (prints a message and does not return).

  `relic funcs` says why each name was given (`[auto: assert() names it]`). On stripped `bash`
  this finds `shell_getc`, `execute_coproc` and `vidomove_dispatch`, among others.
- **Readable variable names.** The pseudocode names variables by how they are used, instead of
  `v1`, `a1` and `var_c`:
  - loop counters are `i`, `j`, `k`;
  - results of known calls are `fd = open(...)`, `fp = fopen(...)`, `len = strlen(...)`,
    `buf = malloc(...)`, `home = getenv("HOME")`;
  - results of the program's own functions are named after them: `lines = count_lines(...)`;
  - types give `FILE *fp` and `struct stat st`;
  - an argument is named after the parameter it is passed as: `read(fd, buf, count)`;
  - `count`, `total` and `result` are recognised.

  Your own names always win, a suggestion never takes a name already in use, and project files
  are unchanged. Use View > Automatic names, or `--no-auto-names` on the command line, to see the
  generated names instead.
- **x87 floating point (32-bit x86).** Functions using `float` and `double` decompile to C rather
  than `__asm("fld ...")`:

  ```c
  float scale(float a1, float a2)
  {
      return a1 * a2 + 1.5f;
  }
  ```

  This covers `float` and `double` parameters, results and call arguments (`printf("%f")` too),
  comparisons, conversions and the rounding-mode switch around a C cast. `long double` stays as
  `__asm`.

## Improved

- At -O0, a parameter is used directly instead of through the stack slot the compiler copies it
  to (`var_1c = argc` is gone).
- A variable that indexes a stack array reads as `buf[i]`, not `i[buf]`.
- Stack stores that nothing reads are left out of the pseudocode.

## Fixed

- `pop ss` in a function no longer stops it from decompiling.
- A `float` constant near `FLT_MAX` no longer stops a function from decompiling.

## Build

- The CI and release workflows use the Node.js 24 versions of their actions. Their Ubuntu runner
  image is pinned to 24.04.
