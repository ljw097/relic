# Relic 1.6.0

Relic measured against Ghidra, angr, RetDec, radare2 and LIEF, with the pseudocode bugs that
comparison turned up fixed. Structs whose fields share a register now read like the source.

## Benchmarks

Stripped builds of brotli, Lua and zstd (-O0, -O2, -O2 without `.eh_frame`, AArch64), against
the other open-source tools. Everything, with the method and caveats, is in
[docs/benchmarks.md](../benchmarks.md); the scripts are in `tools/` (`compare_tools.py`,
`compare_formats.py`, `compare_decompilers.py`, `bench_charts.py`).

- **Function detection:** Relic has the best F1 of the code analysers in every build
  (0.963–0.986; Ghidra 0.73–0.98, angr 0.89–0.97, radare2 0.73–0.90), with or without unwind
  tables, and is 3–5× faster than angr and 4–27× faster than Ghidra.
- **Decompiler output that is valid C:** zstd 92% (RetDec 83%, Ghidra 69%, angr 41%), brotli 82%
  (RetDec 82%, Ghidra 69%, angr 49%), lua 98–99% (Ghidra 95–97%, RetDec 92–97%, angr 88–91%).
  Ghidra's decompiler is faster per function; Relic is 3.5–8.5× faster than angr's.

## New

**Structs whose fields share a register.** `struct pair { int a, b; }` travels in one register;
it now shows as the struct, on x86-64 and AArch64, in parameters and results:

```c
struct pair swap(struct pair a1)
{
    return (struct pair){ a1.b, a1.a + 1 };
}
```

Floats packed in one register still show as before.

**AArch64 struct results without a header.** A function writing where `x8` pointed on entry
returns a big struct: it takes that pointer as a first parameter `result`, and its callers pass
one buffer for it (`make(buf_30, argc, 7)`), where it used to read `*x8 = a1;`.

**x86 `shrd` / `shld`** read as the shifts they are, `(a >> n) | (b << (64 - n))`, not an
`__shrd()` call no compiler knows.

## Fixed

Pseudocode that gcc rejected, found by the benchmark (valid C on zstd went from 122 to 275 of 290
functions, on Lua from 249 to 293 of 294):

- Arithmetic C allows only on integers (`p * 8`, `p & 7`, two pointers of different types
  subtracted) casts the pointers to `int64_t`.
- A struct pointer read from an integer array or an unnamed global is cast before `->`
  (`((struct s_18 *)a1[3])->f_18`, which Lua's `lua_State` accesses are full of).
- An offset added to a `char *` prints as a number, never as a string literal at that address.
- A call through a local that isn't typed as a function pointer gets a cast.
- A recovered struct no longer declares a flexible array member alone (`[0]`) or in the middle
  (its length runs up to the next field).
