# Relic 0.1.0 (베타)

리버싱과 포너블용으로 만들고 있는 디스어셈블러·디컴파일러 Relic의 첫 릴리스입니다.

아직 베타라서 출력 형식이나 Python API는 다음 버전에서 바뀔 수 있습니다. 그래도 바이너리를 열고,
분석하고, 의사 코드를 읽고, 디버거로 따라가는 기본 흐름은 이제 실제로 쓸 만합니다. 목표로 잡은
IDA Pro 9 + Hex-Rays와 비교하면 대략 76% 정도 왔다고 보고 있습니다.

## 설치

```sh
python3 -m venv .venv
.venv/bin/pip install relic_re-0.1.0-py3-none-any.whl     # 아래 Assets에 있는 wheel
.venv/bin/relic gui ./binary
```

Linux에서 Python 3.10 이상이 필요합니다. capstone, pyelftools, pefile, PySide6는 같이 설치됩니다.
디버거를 쓰려면 `gdb`가 있어야 하고, 다른 아키텍처 바이너리는 `gdb-multiarch`와 `qemu-user`도 필요합니다.
어셈블해서 패치하는 기능은 `pip install 'relic-re[asm]'`로 따로 설치합니다.

## 무엇이 들어 있나

- 파일 포맷은 ELF(실행 파일, 공유 라이브러리, `.o`, 코어 덤프)와 PE를 중심으로, COFF 객체, `.a`
  아카이브 멤버, Intel HEX·S-record, raw 덤프까지 엽니다. raw 펌웨어는 적재 주소도 추정합니다
  (`--base auto`).
- 디컴파일까지 되는 아키텍처는 x86/x64, ARM32, AArch64, MIPS32, RISC-V(RV64GC)입니다. PowerPC는
  아직 디스어셈블만 됩니다.
- 분석: 함수 찾기, 점프 테이블을 `switch`로, 데이터 참조, 돌아오지 않는 함수, stripped 바이너리의
  `main` 찾기, 어떤 컴파일러와 libc로 빌드했는지 알아내기.
- 정적 링크된 stripped 바이너리에서는 FLIRT 방식 시그니처로 라이브러리 함수에 이름을 붙입니다.
  테스트 바이너리에서 원래 심볼이 있던 함수의 83~94%를 찾았고, 틀린 이름은 없었습니다.
  시그니처 파일은 설치된 툴체인에서 바로 만들 수 있습니다(`relic sigs build --system`).
- 디컴파일러는 if/while/for/switch를 복원하고, 메모리 접근 패턴으로 구조체를 알아내며, 직접
  타입을 지정할 수도 있습니다(`Y`). 부동소수점, libc·Windows API 원형, C 헤더 가져오기도 됩니다.
  출력을 다시 컴파일해서 원본과 같이 동작하는지 확인하는 테스트도 있습니다.
- GUI에는 리스팅, CFG 그래프, 의사 코드, 헥스 뷰가 있고, 이름·주석·북마크·검색·바이트 패치와
  모든 편집의 되돌리기가 됩니다.
- 디버거는 GDB/MI 위에 pwndbg 같은 화면을 얹었습니다. 로컬 실행, gdbserver, qemu-user, 실행 중인
  프로세스에 붙기가 되고 레지스터, 스택, vmmap, glibc 힙을 볼 수 있습니다.
- Python 콘솔, `relic script`, 플러그인으로 스크립트를 짤 수 있습니다.
- 작업 내용은 바이너리 옆 `<binary>.relic.json`에 저장되고, 스냅숏·버전 기록·병합·Lumina 같은
  이름 공유도 됩니다.
- 포너블용으로 checksec, 위험한 함수 호출, 상수가 아닌 포맷 문자열, ret2win 후보를 찾아 줍니다.
